# Задание агенту: нативный холст черновиков в rhun

## Цель и границы

Добавить в `vshvedov/rhun` отдельную вкладку «Черновик» на существующем ASM-стеке. На ней пользователь рисует схемы и интерфейсы, объединяет элементы во фреймы, принимает предложения модели, генерирует HTML/CSS из структурированного описания и переключает граф в 3D-проекцию распределённого состояния.

Рабочий результат первой очереди — нативная вкладка с основной механикой Excalidraw, собственным форматом сцены и явно ограниченным обменом `.excalidraw`. Полная совместимость со всем Excalidraw не является критерием первой очереди. Каждую поддерживаемую возможность и ограничение описать в таблице совместимости.

В исполняемое приложение не добавлять WebKit, Chromium, Electron, React, DOM или JS-движок. Новые runtime-модули писать на ASM в соглашениях rhun. Инструменты сборки и проверки могут использовать существующий Python/shell-стек репозитория. Добавление нативных библиотек или нового языка исполнения — отдельное изменение архитектуры, не часть этого задания.

Первичная целевая среда: Linux x86-64. Windows и macOS проверяются отдельно в финальной фазе; непроверенную платформу не объявлять поддержанной.

Перед изменениями сверить актуальный HEAD и локальные инструкции. Эти SHA служат ориентиром исследования, а не командой откатить рабочий проект.

Реальные точки опоры в rhun:

- `src/app/app.s`: оболочка, вкладки, маршрутизация ввода и отрисовки.
- `src/app/session.s`: сохранение сессии; уточнить фактический контракт.
- `src/rhun.inc`: общие структуры и соглашения.
- `src/ui/ui.s`: immediate-mode UI, состояния мыши, hit testing.
- `src/gfx/canvas.s`, `raster.s`, `font.s`: растеризация, пиксельный буфер, текст.
- `src/json.s`: парсер JSON с arena; данные документа живут в памяти парсера.
- `src/plat/headless.s`: offscreen-отрисовка и scripted runs.
- `build.sh`: собирает `.s` через GNU as/ld. Режим `test` собирает тестовые бинарники, но сам не выполняет их.

## Правила работы агента и коммитов

1. Создать рабочую ветку от согласованного состояния проекта. Сначала проверить `git status`, локальные инструкции и существующий способ запуска тестов; сохранить пользовательские изменения.
2. Выполнять фазы последовательно. Между фазами проект должен собираться и оставаться пригодным для запуска.
3. Каждая фаза заканчивается одним логически целостным коммитом после прохождения её проверок. Этапы внутри фазы — рабочие шаги, отдельные коммиты для них не обязательны.
4. Перед каждым коммитом проверить diff, выполнить относящиеся к фазе проверки и `git diff --check`. Добавлять в индекс только файлы этой фазы.
5. Вести `docs/native-canvas-progress.md`: фаза, сделанное, точные команды и результаты проверок, известные ограничения. При создании коммита не записывать заранее его неизвестный SHA; SHA сообщать в отчёте после коммита.
6. Не считать компиляцию доказательством правильного поведения. Запускать тестовые программы и проверять их результат в принятом в репозитории формате. Не обновлять эталоны, чтобы скрыть регрессию.
7. При провале проверки исправлять текущую фазу. Если обнаружена внешняя блокировка, сохранить конкретный диагноз и отделить подтверждённый результат от незавершённого.
8. Все коммиты выполнять локально. Публикация, push и merge требуют отдельного задания.

## Архитектурные инварианты

- **Scene IR** — редактируемые фигуры, текст, фреймы, группы, привязки, z-order и метаданные. **UI IR** — смысл интерфейса: компоненты, раскладка, стили и действия. **Graph/State IR** — зависимости, сегменты, объекты, реплики и события. Это разные модели с явными связями по ID.
- ID сохраняются при перемещении, сохранении, раскрытии и сворачивании. Удаление объекта не оставляет висячих ссылок.
- Свёртка меняет видимую проекцию, а не исходный граф. Граничная связь хранит ID исходных рёбер; после раскрытия восстанавливается исходная структура.
- UI IR и предложения модели ссылаются на ID сцены и её ревизию. Изменение сцены делает предложение устаревшим; применение требует проверки совместимости.
- Данные IR принадлежат документу. Не хранить долгоживущие указатели в arena `src/json.s`: другой разбор/reset способен их инвалидировать. Нужны копирование или явно выделенное хранилище документа.
- Модель предлагает данные и патчи. Проверенный код применяет их транзакционно. Ответ модели не превращать напрямую в исполняемый ASM.
- Генерация HTML и отображение произвольного HTML — разные функции. Нативный предпросмотр рендерит только поддерживаемый UI IR, а не веб-страницу с полной семантикой браузера.

**Коммит:** `docs(canvas): define native canvas architecture and acceptance gates`

## Фаза 1. Вкладка и жизненный цикл документа

1.2. Подключить создание, фокус, отрисовку, resize и закрытие. Холст использует существующий графический target и clip stack.

1.3. Реализовать преобразование экранных/мировых координат, pan и zoom относительно указателя. Сначала показывать сетку и несколько фигур из фикстуры.

1.4. Подключить путь документа, dirty-индикатор и правило закрытия изменённого документа через существующий UI. До готовности сериализации не выдавать сохранение за реализованное; хранить минимальную фикстуру или временное состояние явно.

### Готовность и проверки

Можно открыть два независимых черновика, переключать их, масштабировать, менять размер окна и закрывать. Ввод не перетекает в редактор кода. Обратное преобразование координат проверено на разных масштабах; clip stack не повреждён после отрисовки. Существующие вкладки проходят smoke-проверку.

**Коммит:** `feat(canvas): add native canvas tab and viewport lifecycle`

## Фаза 2. Редактор черновика и транзакционная история

### Этапы

2.1. Добавить перечисленные в фазе 0 инструменты. Отделить предпросмотр текущего жеста от подтверждённой сцены.

2.2. Реализовать hit testing с учётом z-order и zoom, одиночное/рамочное выделение, перемещение и изменение размера.

2.3. Реализовать текстовый ввод на нативном пути rhun: UTF-8, курсор, удаление, переносы, вставка и фокус. Проверить ввод кириллицы; поддержку IME описывать только после отдельного теста.

2.4. Добавить привязки стрелок к фигурам. Перемещение фигуры пересчитывает привязанный конец; удаление фигуры либо удаляет, либо отвязывает связи по документированному правилу.

2.5. Реализовать механику шарика: hover у границы показывает «+»; drag в пустоту создаёт узел и связь с меню «шаг / вопрос / решение / ограничение»; drag на фигуру предлагает смысл связи. Создание узла, ребра и выбор типа — одна транзакция. Escape отменяет жест целиком.

2.6. Добавить undo/redo на уровне команд/патчей. Один drag — одна запись истории, а не запись на каждый mousemove. После undo новая правка корректно отбрасывает ветку redo.

2.7. Реализовать собственный версионированный JSON-формат: открытие, сохранение, восстановление сессии. Проверять JSON, числа и ссылки до замены текущего документа; запись проводить через временный файл с заменой по существующей платформенной практике.

### Готовность и проверки

Создать фрейм со схемой, переместить связанный узел, изменить текст, удалить фигуру, выполнить undo/redo и переоткрыть документ. ID, связи и геометрия сохраняются. Тесты покрывают отмену жеста, порядок истории и некорректный файл, который не портит открытый черновик. Долгоживущая сцена выдерживает последующий разбор другого JSON.

**Коммит:** `feat(canvas): implement draft editing bindings and undo history`

## Фаза 3. Фреймы, стиль и обмен с Excalidraw

### Этапы

3.1. Добавить группы, поворот, z-order и изображения на базе существующих декодеров rhun. У фреймов — членство, выделение содержимого и отсечение; вложенность собственного формата не приписывать формату Excalidraw.

3.2. Перенести нужные алгоритмы рисованного вида: воспроизводимые штрихи по seed и поддерживаемые заливки. Перенос исходников сопровождать сведениями о происхождении и обязательными уведомлениями лицензий.

3.3. Реализовать импорт/экспорт поддерживаемого подмножества `.excalidraw`: геометрия, текст, seed, группы, фреймы и привязки. Отдельно решить embedded files, метрики шрифтов и неизвестные поля.

3.4. Не терять неподдерживаемые элементы молча: сохранять исходные данные там, где это возможно, либо выдавать конкретное предупреждение/placeholder. Экспорт собственных семантических расширений документировать отдельно.

3.5. Добавить SVG-экспорт выбранного фрейма как переносимый снимок черновика. При наличии простого существующего PNG-пути использовать его; не блокировать фазу новым PNG-кодеком.

### Готовность и проверки

Есть фикстуры собственной сцены и внешнего `.excalidraw`, двусторонний семантический round-trip для поддерживаемых элементов. Повторный кадр не меняет рисованный контур. Отдельно описаны расхождения шрифтов и неподдерживаемые данные. Результат внешнего экспорта проверен в Excalidraw, если доступна такая среда; иначе эта проверка отмечена как невыполненная.

**Коммит:** `feat(canvas): add frames sketch styling and excalidraw interchange`

## Фаза 4. UI IR и генерация HTML/CSS

### Этапы

4.1. Реализовать валидатор UI IR: типы компонентов, дерево, ID, ссылки на сцену, поддерживаемые свойства и ревизия источника. Дерево компонентов не содержит циклов; граф смысловых зависимостей может их содержать.

4.2. Добавить ручную семантическую разметку фигур: прямоугольник можно назначить кнопкой/полем/карточкой; назначение хранится отдельно от геометрии.

4.3. Реализовать детерминированный экспорт выбранного UI-поддерева в HTML/CSS с экранированием строк, устойчивыми именами и картой `scene ID ↔ component ID ↔ generated element`. Предпочесть явный небольшой словарь стилей; полную совместимость Tailwind не заявлять.

4.4. Открывать сгенерированные файлы обычными вкладками rhun. Смена выделения на холсте позволяет перейти к связанному компоненту в коде; для обратного перехода использовать карту генерации.

4.5. Подготовить однонаправленный контракт: UI IR — источник генерации. Правки произвольного HTML пока не разбираются обратно в сцену и не должны молча затираться повторной генерацией. Уведомлять о рассогласовании и сохранять ручную версию отдельно.

### Готовность и проверки

Размеченный фрейм с формой экспортируется повторяемо, текст с кавычками/угловыми скобками корректно экранируется, ссылки ведут к нужным компонентам. Неподдерживаемые свойства получают диагностику. В первой очереди действия представлены идентификаторами, без обещания исполняемой бизнес-логики.

**Коммит:** `feat(canvas): add semantic UI IR and deterministic HTML export`

5.4. Отдельно обозначить, что показывается проекция UI IR. Произвольный HTML/CSS/JS не исполнять и не представлять этот режим как браузерный preview.

Тот же UI IR формирует HTML-экспорт и нативную карточку. Есть проверки геометрии на эталонных раскладках и разных размерах фрейма. Фокус и hover не ломают перемещение фигур. Различия нативной и браузерной типографики описаны; попиксельное совпадение не обещается.

**Коммит:** `feat(canvas): render UI IR previews with native layout`

## Фаза 6. Предложения модели и прогрессивная детализация

### Этапы

6.1. Сначала реализовать полный путь на локальных JSON-фикстурах. Затем подключить существующий механизм внешнего агента, если он умеет возвращать структурированный результат. Панель, показывающую логи, не считать автоматически транспортом запросов; при отсутствии подходящего пути добавить адаптер внешнего процесса/файла результата по контракту.

6.2. Запрос включает выделенные ID, их контекст, ревизию сцены, допустимые операции и нужную задачу: детализация этапа либо преобразование фрейма в UI IR. Не отправлять проект целиком по умолчанию.

6.3. Ответ — предложение патча: новые/изменённые элементы, связи, семантические назначения и пояснение. Не разрешать неизвестные операции, дубли ID и висячие ссылки.

6.4. Показывать новые элементы полупрозрачным слоем без изменения документа. Разрешить выбор подмножества; автоматически включать необходимые зависимости либо выдавать понятную диагностику.

6.5. Принятие выбранных элементов — одна транзакция и один undo. Отклонение не меняет сцену. Ответ на устаревшую ревизию требует повторной проверки/перегенерации, а не безусловного применения.

6.6. Добавить раскрытие/сворачивание подграфа этапа. Повторное раскрытие возвращает существующие узлы, не создаёт дубликаты. Сводный узел показывает прогресс и число блокировок, рассчитанные по документированным правилам.

### Готовность и проверки

Офлайн-фикстура проходит полный цикл запрос → preview → частичное принятие → undo → redo. Невалидный и устаревший ответы оставляют документ целым. Повторное раскрытие не меняет количество исходных узлов. Сетевые/провайдерские проверки отдельно от детерминированных тестов.

**Коммит:** `feat(canvas): add validated AI proposals and progressive decomposition`

## Фаза 7. 3D-проекция распределённого состояния

### Этапы

7.1. Выделить из приложенного HTML данные `nodes`, `edges`, `segments`, `events`. Перенести в Graph/State IR; отличать логический объект от его реплик и версии схемы от версии состояния.

7.2. Перенести алгоритмы `rotate`, `perspective`, `visibleGraph` и проверки попадания в ASM. У образца Canvas 2D, собственная математика и сортировка по глубине — WebGL для воспроизведения этого демонстрационного вида не требуется.

7.3. Реализовать native drawing рамок сегментов, сфер/маркеров, стрелок и подписей. Определить clipping, порядок отрисовки и выбор узлов; сортировку образца не выдавать за универсальную систему видимости сложных 3D-сцен.

7.4. Добавить переключение 2D/3D, orbit/zoom, выбор узла, инспектор и timeline событий. Обе проекции используют одинаковые исходные ID и данные; 3D-координаты — отдельное представление.

7.5. Реализовать свёртку сегментов с агрегированными граничными связями и списком исходных edge ID. Общий контракт остаётся одним объектом, а не копируется в каждый сегмент.
